# T1.8 Nơi lưu và cách agent task đọc gói OpenSpec (2026-10-14)

## Mã hiện có

- Worktree của task do `WorktreeProvisioner.EnsureWorktree` tạo ([worktree_provisioner.go](../../../../../../backend-go/services/task-service/internal/adapter/grpcclient/worktree_provisioner.go)): nhánh `task/<task-id>`, repo là repo đầu tiên theo `position` của project, **không gửi `base_ref`**. Request-service không chọn được nhánh nền cho task.
- Git-gateway chạy `git worktree add <path> -b <branch> <baseRef>` ([executor.go:571](../../../../../../backend-go/services/git-gateway-service/internal/adapter/localgit/executor.go)); `baseRef` rỗng bị git 2.54 từ chối (`fatal: invalid reference:`) khi thử tay. Các lần e2e trước vẫn tạo được worktree task, nên đường chạy thật có cách khác (relay hoặc mặc định ở nơi tôi chưa lần ra): **cần xác nhận lại ở T2.11**, không dựa vào giả định.
- `ProposalWorkspace` (nhánh `request/<số>-proposal`) vẫn là stub (T2.6).

## Thử trên bản sao

Nhánh `request/9001-proposal` chứa gói mẫu (T1.5, lần 2); một worktree task tách từ nhánh khác (`task/spike-18`).

| Cách | Kết quả |
|---|---|
| Worktree task tách từ nhánh mặc định có thấy `openspec/`? | **Không** |
| `git show request/9001-proposal:<đường dẫn>` từ worktree task | Đọc được (chung kho đối tượng/nhánh) |
| `git restore --source request/9001-proposal --worktree -- openspec/changes/<id>` | Chép được nhưng để lại `?? openspec/` ⇒ làm bẩn diff/commit của task |
| Agent (`claude --print --model haiku`, chỉ `Read`, `Bash(git show:*)`) đọc `Verify:`, `Done when:` của T1.3 và tên scenario đầu | **Đúng cả ba mục**, không chép gì vào worktree |

## Quyết định

1. **Không chép gói vào worktree task.** Prompt task nêu: tên nhánh `request/<số>-proposal`, id thay đổi, "đọc bằng `git show <nhánh>:openspec/changes/<id>/<file>`, mỗi lệnh một `git show`, không chép vào worktree".
2. Hợp đồng của chính task (bốn dòng `Serves/Code/Verify/Done when`) đã đi theo `Description` của task: parser đưa các dòng thụt hai ô vào `Description`, nên agent biết việc cần làm kể cả khi không đọc gói. Gói chỉ là ngữ cảnh bổ sung (scenario, thiết kế).
3. Việc phải làm: T2.6 (tạo nhánh, ghi và commit gói trên nhánh đó; chặn push), T2.11 (đưa tên nhánh và id thay đổi vào prompt task; `allowedTools` cho agent ghi thêm `git show`), T2.11 kiểm lại cách worktree task được tạo thật (đã nói trên).
